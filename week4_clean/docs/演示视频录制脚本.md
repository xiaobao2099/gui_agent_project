# 端到端演示视频 · 录制脚本

> 说明：本轮执行环境为无桌面显示的 Linux 容器，无法抓取真实 Win11 桌面画面，因此视频未录制。以下脚本按秒级分镜写好，在 Win11 本机用任意录屏工具（Win+G / OBS / QQ 录屏）即可一次拍完，时长控制在 3 分 30 秒以内。

---

## 0. 录制前准备（不计入视频时长）

| 项目 | 要求 |
| --- | --- |
| 录制分辨率 | 1920×1080，全屏录制，关闭通知弹窗 |
| 录屏工具 | Win+G（Xbox Game Bar）或 OBS，帧率 30 fps |
| 画面设置 | 关闭桌面图标整理、关闭壁纸轮播、鼠标指针可见 |
| 服务状态 | 先确认推理服务在线：浏览器打开 `http://<内网IP>:6006/docs` 能看到接口页 |
| 客户端 | 已安装依赖，`client_v2.0.py` 的 `SERVER_URL` 与 `ALLOWED_HOSTS` 已改为内网地址 |
| 命令行 | 打开一个 cmd 窗口，字号调至 18 号，便于后期看清 |
| 记事本 | 事先关闭所有记事本窗口，确保任务从零开始 |

## 2. 必须出现的 5 个画面（验收点）

1. **架构图**：证明是客户端/服务端分离，不是本地跑模型。
2. **24 条单测通过**：证明代码可回归。
3. **20 条验收用例 PASS**：证明功能被逐条验证过。
4. **记事本真实被打开并写入文字**：证明端到端真跑通，不是录屏拼接。
5. **日志里的差分值**：证明鲁棒性机制在真实运行，不是纸面设计。

## 3. 录制时容易翻车的点

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 运行框被重复输入「notepad」填满 | 模型连续输出 type notepad，客户端每轮都执行 | 停止录制，清空运行框，重跑；这是已知的模型重复输出问题 |
| 输入「notepad你好世界」粘连 | 上一动作未确认完成就执行下一步 | 把 `SCREEN_STABLE_DELAY` 从 1.2 调到 2.0 再录 |
| 点击后界面没反应但日志显示成功 | 差分噪声被误判为变化 | 确认没有开动画壁纸，必要时临时把阈值调到 2.0 |
| 客户端卡在「推理请求失败」 | 服务端未启动或地址错 | 先在浏览器验证 `/docs` 可访问 |
| 记事本没打开 | Win+R 被安全软件拦截 | 提前在安全软件里放行 python.exe |

## 4. 备用录制方案（服务不可用时）

若录制当天推理服务不可用，改用「离线证据版」演示，时长 1 分钟：

1. 展示 `test_artifacts/results.csv`（20 条用例真实结果）；
2. 展示 `logs/client_v2.log` 历史片段（含真实的模型输出与差分值）；
3. 展示三张真实截图 `img_0`～`img_2` 与对应的差分计算结果；
4. 口播说明：模型侧能力已在第 3 周真机验证，本次演示聚焦客户端执行链路。

此方案不冒充端到端实拍，需在视频开头用字幕标明「离线证据演示」。
